Incident brief · desktop agent

Grok Bot would not start:
missing tree-sitter module

A corrupted app.asar broke native dependency resolution. Restoring the pre-patch archive fixed launch in under a minute. v1.1.0 leaves a healthy archive alone and will not copy a backup that is also missing tree-sitter.

The bug

Uncaught Exception
Error: Cannot find module 'tree-sitter'
Require stack: .../app.asar/dist/electron-main/main.js
  • 1Main process requires tree-sitter for shell parsing.
  • 2It sets NODE_PATH to app.asar/dist/deps.
  • 3A same-day app.asar rewrite left only empty dep stubs.
  • 4Real packages still lived in app.asar.unpacked, unreachable.

The fix

  • 1Quit every Grok Bot process.
  • 2Keep the broken asar as forensic backup.
  • 3Restore app.asar from the pre-patch backup.
  • 4Relaunch - window stays open, error gone.
# resources folder under Local\Programs\Grok Bot
Copy-Item app.asar app.asar.broken-... -Force
Copy-Item app.asar.bak-subject-fix-... app.asar -Force
# launch Grok Bot.exe → OK

Takeaways for Bot / desktop Electron apps

  • ANever repack asar without verifying dist/deps/*/package.json and native .node files are either in the archive index or resolved via app.asar.unpacked.
  • BKeep a known-good asar backup before any subject/string patch so restore is one copy command.
  • CIf you must patch: rewrite NODE_PATH to replace app.asar with app.asar.unpacked, or ship real dep files inside the asar.
